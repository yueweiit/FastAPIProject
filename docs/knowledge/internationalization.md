# 国际化现状与渐进扩展约定

## 当前能力

截至 2026-10-19 静态核对，项目是简体中文界面，尚未建立通用国际化框架、翻译资源目录、统一翻译函数、语言选择器或用户语言偏好。不能将跨境店铺、多币种或 OA 中西文表单名描述为已支持多语言界面。

| 范围 | 当前实现及代码依据 |
| --- | --- |
| 页面 | [templates/index.html](../../templates/index.html) 声明 lang="zh-CN"；菜单、表单、按钮、提示及动态表格直接写中文。根目录 index.html 是有差异的副本 |
| 状态 | 页面比较 new/stable、角色等内部编码后写中文标签；导入状态也有局部映射，无统一翻译资源 |
| 错误 | [routers/](../../routers/) 多使用中文 HTTPException.detail；Pydantic 校验消息可能为英文；页面 formatApiError 直接组合消息。EIMS 已有稳定错误码，但后端 ERROR_MESSAGES 和页面 initializeAuth 各自维护中文映射 |
| 业务文本 | [models.py](../../models.py) 的商品/店铺/产品线名称、备注和来源名称为单字段；没有语言键或翻译关联表 |
| 数字/货币 | 页面 reportMoney、formatProfitLossAmount 使用 zh-CN 和人民币符号；销售同时显示原币代码与汇率，部分数值用 toFixed。展示语言不能改变人民币核算口径 |
| 日期/时区 | 页面用 sv-SE 输出日期输入值；后端 Date/无时区 DateTime、本地 date.today 与 Asia/Shanghai 快照并存；认证显式使用 UTC。stores.timezone 为已保存配置，不能据此认定所有业务都按店铺时区转换 |
| Excel | [商品导入服务](../../services/product_import.py)、[商品](../../routers/products.py)、[批次](../../routers/batches.py)、[销售](../../routers/sales.py)、[报表](../../routers/reports.py) 的工作表名、列名、校验及备注多为中文，无统一语言参数；日期/金额格式在导出代码设置 |
| 其他输出 | 当前注册接口未见 PDF、邮件、通知或独立打印模板服务；Excel 打印布局不构成多语言打印系统 |

依赖以 [requirements.txt](../../requirements.txt) 为准；当前无前端 package.json。现阶段没有可供复用的全局翻译键约定或语言回退实现，下面均为后续建设建议。

## 不能当作界面文案翻译的契约

1. **内部编码**：角色、商品类型、映射状态、报表科目键和期间 current/previous/ytd 保持稳定，标签另行映射。字段入口见[数据字典](data-dictionary.md)。
2. **文件格式**：商品导入的中文列名、类型别名和“商品导入”工作表，以及销售文件的“订单详情”/来源列名都参与解析。未来导出翻译须保留旧格式读取兼容，不能只改表头。依据：`parse_product_import`、`_read_import_file`。
3. **外部取数名称**：[oa_office_expenses.py](../../services/oa_office_expenses.py) 使用申请日期、管理支出等中西文组件名及部门名匹配；店铺名称还参与工资归属。改名需要核对 OA 契约和映射，不能随前端语言自动翻译后用于业务判断。
4. **业务数据**：SKU、订单标识、来源原文和原始结算 JSON 保留原值。产品名称的多语言维护与界面标签翻译是两项需求，需要另行确认存储、编辑和缺失语言回退策略。

## 新功能的渐进实施建议

| 阶段 | 建议 | 兼容要求 |
| --- | --- | --- |
| 首个实际多语言需求 | 在现有原生页面建立轻量文本字典和统一取词入口，先接入新功能；语言资源路径、支持语言经该任务确定 | 本次不安装依赖、不创建翻译运行代码；不能假定已有 t() |
| 翻译键 | 建议按“模块.对象.用途”组织，如 sales.import.pending；参数替代拼接完整句子 | 键与内部状态解耦；占位参数转义，避免翻译文本直接注入 HTML |
| 语言选择与回退 | 建议默认 zh-CN，缺键回退默认语言并在开发检查中报出；明确用户偏好和浏览器语言的优先顺序 | 支持哪些语言需业务确认；不能宣称已有英文/西班牙文支持 |
| API 错误 | 逐步扩展稳定 code 和参数，前端翻译；参考现有 SSO 错误码 | 保持既有 detail 及状态码兼容；不要求客户端解析中文做判断 |
| 区域化 | 汇总日期、金额、数量、币种格式化；分别确定显示 locale 与业务时区 | 不更改 Decimal 精度、汇率日期、自然日 FIFO 和财务期间算法 |
| 文件与业务数据 | 导出增加显式语言能力，保留旧导入别名；业务名称翻译另评估数据模型 | 不为局部页面任务自动加表或回填历史数据 |

新增用户可见文本应集中组织并登记待翻译项；后续建立正式机制时同步所有已支持语言。当前无统一机制的功能应在实施方案说明文本组织方式，不借局部修改批量重写旧页面。

## 交付检查与已知限制

- 检查静态 HTML、动态模板、错误提示、状态、空态、Excel 表头/校验和文件名；不得只检查按钮。
- 实现语言切换后验证缺键回退、占位参数、长文案、区域化及两份页面的任务相关差异；本次没有运行此类浏览器测试。
- 当前硬编码、SSO 两处映射、固定人民币展示及外部名称匹配均有源码依据；统一时区和真实 OA 改名影响待验证。长期风险入口沿用[架构风险清单](../../PROJECT_ARCHITECTURE.md#9-当前已知风险)。

## 财务工作台增量

[static/financial-control.js](../../static/financial-control.js)集中zh-CN文案，通过document.documentElement.lang选择并回退中文；未增加依赖或全站语言切换。稳定状态/科目编码与展示标签分开，服务端新错误用code/message；后端配置标签/Excel继续现有中文契约。当前没有已支持的第二种语言，不能声称完整多语言已经实现。

[static/page-interactions.js](../../static/page-interactions.js) 的更正原因、校验、确认/取消及撤销说明也采用局部zh-CN字典和中文回退。批次业务日期按无时区填写值提交，保持自然日，不按浏览器区域或UTC偏移换日；这不表示其他模块已统一时区。

销售文件导入的店铺标签、选择/绑定/加载提示和导入按钮通过同一字典的text入口维护，两份首页使用data-sales-import-text及salesImportText。新增API错误以稳定code/message返回；Excel新增店铺列沿用当前中文导出契约，未来多语言导出仍待明确语言参数。

批次操作列新增的编辑/删除标签、受限原因、编辑说明和保存反馈也通过 `PageInteractions.text` 的 `batch*` 键维护，语言缺失时回退 zh-CN。沿用已有表单标签；本次没有新增支持语言或变更导入/导出契约。

批次修改日志弹窗复用该字典的`batchLog*`标签、字段映射、分页、空态和错误提示；日志绝对时间含UTC偏移，按浏览器语言/时区显示，快照金额按精确字符串展示，不将其转换成浮点数。历史发货/入库业务日期仍原样展示，不统一改动其他时间口径。
