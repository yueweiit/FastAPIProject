# 成本、费用与月度版本

本模块在原批次、FIFO明细和人工损益之上追加凭证及核对层，不改写历史出库成本。2026-10-19已完成代码及隔离验证，默认开关关闭；目标MySQL结构及正式账单仍待验收。入口：[总索引](../../knowledge/README.md)、[流程](workflow.md)、[代码映射](code-map.md)、[字段字典](database.md)、[API](api.md)。

## 已确定的业务口径

- 晚到成本追溯原销售月份。9月入库100件、售40件，10月补充运费200元：9月已售成本增加80元，未售库存增加120元。旧月度版本保持原值，复核后保存9月新版。
- 销售继续沿用现有订单创建日归月；独立退款/调整沿用结算日优先规则。回款按实际到账日留档，不自动变成收入。
- 成本调整是“差额”，不是重录整张账单；采购、头程、尾程和其他成本分别确认。四个科目都完成实际核对后状态才为actual；零差额也可确认原金额。
- 费用明细先保存草稿，管理员确认后入账。每店铺/月/科目显式选择manual或ledger，二者替换、不相加；切换时保留原人工值。ledger仍有草稿时相关费用和利润为null并提示。
- 平台差额分类只拆分原已扣金额，不再次记费。关联结算的费用凭证只作核对；回款按付款ID及原币跨月核对，差额保留。
- 已结束的完整自然月可保存不可变版本；存在未核对事项时状态为needs_review，并保存警示。没有严格锁月或禁止后续补录；相同来源摘要复用既有版本。

## 范围和限制

后台：[financial_control.py](../../../routers/financial_control.py)；页面为报表导航“成本、费用与核对”，实现于[financial-control.js](../../../static/financial-control.js)。使用既有角色、Cookie/CSRF和店铺绑定；不接入新的外部财务系统。

批次仍共享，库存店铺仍从创建人当前绑定推导；本次没有引入仓库/调拨/真实退货流水，也不自动判断CN运费应属于哪个科目。凭证号应含供应商和单号，操作者按实际业务选择分类。实际账单与OA费用仍需人工勾稽，不能把“已保存版本”当作外部财务验收。

## 启用

配置FIFO_FINANCIAL_CONTROLS_ENABLED默认0。先审核八张加法表及外键、唯一约束、InnoDB、精度和隔离级别，再按[运行步骤](../../../PROJECT_RUNBOOK.md#财务增强结构与启用)启用。未执行目标库迁移或部署；不要用启动应用代替结构预检。
