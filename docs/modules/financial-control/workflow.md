# 成本、费用与版本流程

## 事务与审计默认字段

所有财务写入通过 [financial_controls.audit](../../../services/financial_controls.py) 追加审计，并必须 `await`。该函数先在现有事务内 `flush()`，再用 `AsyncSession.refresh(..., attribute_names=...)` 显式加载尚未加载的列，最后保存审计；不会自行提交。MySQL 不通过 `RETURNING` 回填默认时间，不能让同步 `record()` 触发隐式读取，否则会出现 `MissingGreenlet`。更新来源选择时，也须先落库并读取 `updated_at`，使响应、审计与实际记录一致。审计失败与凭证一起回滚，不跳过审计或改用伪造时间。

## 1. 实际成本补差

1. 输入来源凭证、差额、币种和人民币汇率、凭证/汇率日期及科目。CNY固定1；外币必须显式给出正数汇率，不联网猜测。
2. 选择1–100个批次。quantity按首次入账时的批次数量，固化于分配行；后续批次更正不回写原quantity或权重。weight/volume/value需要逐批次填写正数依据。人民币按0.0001元整数单位分摊，先取各份额的整数部分，再按余数从大到小分配剩余单位；同余数按固定批次顺序的后端优先。正、负补差的各批次金额均不反号，合计等于整单金额；原币和权重保留。
3. 预览已售/未售金额，再确认。按product_id、arrived_at、id锁批次，锁内当前读最新成本层，校验该科目修正后不能为负；已作废批次不能新增补差，operator仅自己的批次，admin可跨创建人。作废前的同一request_key仍可幂等重试，旧补差可按原分配反向冲销。
4. 一事务保存调整头、批次分配和审计。request_key与category/source_ref唯一约束防重复；相同请求内容可重试，内容不同返回409。重试仍核对权限并锁批次；quantity模式仅比较原批次集合，不以当前数量生成的权重判冲突，复用原单、原分配和原审计。weight/volume/value仍核对显式权重，所有模式的单据内容或批次集合改变均返回409。
5. 后续查询统一使用“原保存成本＋每原入库件分摊的调整”。销售/损益/产品线按原销售日期重算；库存和持有期间准备按当前已知成本追溯重算。即使凭证10月收到，查询9月当前结果也会包含它；要查看补录前数据须读取已保存旧版。
6. 凭证更正通过有原因的反向单再追加正确凭证，严格按原分配行quantity和金额校验、取反，不用当前批次数量重摊。原单、分配和FIFO单价保留；批次统一通过软作废停用，即使净差额为0也不物理删除原来源。批次编辑入口可按[库存规则](../inventory/workflow.md#编辑与删除)更正绝对目标数量/金额，系统追加差额而不改写旧凭证；该入口仅对admin/operator放开共享批次更正权限，独立补差API仍按原创建人限制。

独立成本调整不改remaining_quantity；批次更正数量则保留已售数并计算新余量，首次冻结cost_basis的原数量/单位成本构成。销售、导入、撤销锁序不变，原Sale.total_cost/profit和SaleCostDetail.unit_cost仍是初始值，响应人民币利润/成本叠加追溯层。自动批次更正凭证is_final=False，不等于四类账单已经核对；旧月度版本需复核后另存。

负成本校验先将单位成本还原为金额，再以当前批次数量与本分配行quantity的较大值为核验尺度，按凭证四位小数HALF_UP后比较科目及总成本，避免非整除分摊的Decimal尾差误拒费用清零。差额分母仍用本分配行quantity（冲销用原行），不能因数量增加而稀释冲回金额；最小负差0.0001元及数量放大后的真实负成本仍拒绝。编辑金额和日志将舍入后的负零规范为0.0000。实现见[financial_controls.py](../../../services/financial_controls.py)的validate_adjusted_cost/post_cost_adjustment与[cost_layers.py](../../../services/cost_layers.py)的editable_cost_values。

## 2. 费用台账与损益来源

新增draft → 管理员确认posted；draft可作废cancelled，posted只能追加相反金额的posted记录。按发生日期归月，币种/汇率固化；正金额表示费用增加（收入类科目表示收入增加），负金额表示对应冲减。

默认使用原人工总额。选择ledger后，该月科目由已确认、未关联平台结算的明细求和；没有明细时为0，有待确认明细时相关金额为null。仅受影响科目的当前/上月/累计按明细重算，其他科目的历史人工比较值保留。损益页ledger科目只读，保存其他科目不会清空人工备选金额；切回manual恢复人工来源。

10跨店汇总保留台账待确认科目的空值，其合计和占比也留空；人工未填写的普通科目仍沿用按0汇总的旧约定。费用确认后，单店及跨店导出恢复使用实际金额。

同一费用如已包含在平台结算差额中，应填写settlement_entry_id，台账只核对、不再扣费。未关联的手录费用和OA之间没有自动语义查重，来源切换前仍需检查凭证及现有科目，避免跨科目重复。

## 3. 平台分类与回款

- 保留原始税费、运费、佣金等平台列；分类合计必须精确等于该行已入账差额费用，允许按原差额方向填写。赔付沿用现有绝对值费用规则，不改原口径。
- 结算月采用结算日期→订单日期→导入日期；历史店铺采用直接店铺→导入批次→创建人当前绑定。缺少直接归属时只读展示并提示，不能分类或关联费用。
- commission/tax/advertising/logistics/other为稳定内部分类。分类变更保留审计，不新增损益金额。
- 实际回款独立保存，按payout_id＋currency汇总该付款ID所有月份的结算和回款；显示差额，不以汇率或人工调平掩盖。反向单保留原到账日期。存在缺失付款ID或差额时月度版本提示核对。

## 4. 月度结果版本

按店铺/月保存P&L、07明细、SKU汇总所需数据、产品线、利润层次、费用/成本来源清单、结算回款核对及warnings。店铺锁串行化版本号，数据库唯一约束兜底；相同request_key重试复用，同一来源摘要也复用。

财务总览、保存新版及版本比较先核对店铺权限，再结束用于读取有效店铺数的 MySQL 事务，等待 OA 只读数据后进入报表采集；同一请求的 OA 结果只读取一次。保存新版在 OA 等待结束后才获取店铺锁，并在新的 MySQL REPEATABLE READ 事务内计算、写入版本及审计。已存在且参数一致的 request_key 直接复用旧版，不依赖 OA 当时是否可用。OA 与 MySQL 之间没有共同快照；OA 更新仍可能影响后续新版本，旧 payload 不改。依据：[financial_control.py](../../../routers/financial_control.py) 的总览/版本路由、[financial_versions.py](../../../services/financial_versions.py) 的 `collect_payload`、`save_version`。

版本payload持久化后不更新；当前数据比较返回利润行差异，来源变化但金额未变也标记changed。更正成本回到原金额仍因来源清单不同生成新版。导出仅读取该payload生成四张单店表和“版本及核对说明”，不取实时数据；跨店10汇总需另行核对各店所选版本，未实现跨店统一版本集。

商品成本后余额、平台费用后余额用于经营核对，正式财务毛利/净利仍以既有损益口径为准。needs_review保存了未解决事项，不能当作无警示的confirmed。内部AccountingPeriod自动快照继续保留，与人工保存的FinancialReportVersion用途不同。

已被费用凭证或结算分类引用的导入不能物理撤销，返回409且不改变库存；保留来源，通过更正凭证处理。财务关联按Store→导入头→结算行锁序，与原导入撤销头锁串行，已撤销来源不能再关联；此限制属于来源完整性保护，不按月份封锁所有业务。

## 页面初始化与筛选

[financial-control.js](../../../static/financial-control.js)先创建店铺/月筛选区，月份沿用损益表当前选择，未选择时由既有defaultProfitLossMonth取浏览器本月；业务表单在配置返回后创建。配置与店铺/当前账号信息独立加载，店铺名称通过转义后展示。管理员依次优先保留有效的本页选择、损益表店铺、账号绑定店铺，最后取首个可访问店铺；运营和查看者仅展示并锁定当前绑定店铺。保留停用店铺的历史查询能力，不改变服务端权限。

财务增强关闭时仍加载基础筛选，保留“尚未启用”提示并隐藏业务区，不查询批次或财务增强明细。“查询 / 刷新”重新检查配置和基础资料，可在加载失败后重试；不会自动启用开关或修改结构。无店铺、未绑定和店铺请求失败分别显示明确原因。

费用发生日期在首次为空时按核算月份设置默认值，用户明确切换月份时重新设置；普通查询刷新或重新打开工作台保留已填写日期和原请求标识。保存响应丢失后，刷新再重试须复用相同日期、金额及request_key，由服务端识别同一提交，不将查询刷新当作费用内容变更。

批次候选单独加载，失败时保留已完成的店铺/月选择，显示警示并继续加载其余报表。初始化中的重复打开复用同一请求，暂禁用筛选和刷新；此时不会因刷新递增串号而丢弃初始化结果。初始化完成后保留显式选择；退出重登清理状态并忽略旧响应。新增提示沿用该模块zh-CN字典，未引入新国际化依赖。回归入口见[代码映射](code-map.md)。

## 页面更正交互

成本、费用、回款反向单和费用草稿作废共用 [page-interactions.js](../../../static/page-interactions.js) 的页面内 dialog，更正原因去除首尾空白后必填且最多1000字；确认前不会请求写接口，取消/Esc/会话退出不会提交。财务模块等待输入时保留目标ID和店铺/月串号，范围切换或退出后丢弃待确认结果。弹窗不替代服务端权限、原分配冲销、审计、幂等和来源完整性校验。
