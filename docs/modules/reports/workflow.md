# 报表流程、公式与快照

管理员或运营作废错误历史批次后，当前动态存货、准备计算和商品库存排除该批次原剩余数量；原销售与成本明细仍保留。单店损益对引用已作废批次的原销售月份将采购/物流/其他FIFO成本、存货跌价准备和销售转销跌价准备留空，相关利润随公式留空并给出待核对警示；产品线报告对应成本亦留空。销售前的历史持有月份也须核对存货跌价费用，不能因该月没有销售就填0，具体范围见下段。旧内部月末快照及人工保存月度版本不覆盖，作废后的当前计算可与旧版比较并另存待核对新版。销售列表保留历史成本但标记needs_review，不能把它当作重新分配后的正确成本。依据：[reports.py](../../../routers/reports.py)、[accounting_periods.py](../../../services/accounting_periods.py)、[financial_versions.py](../../../services/financial_versions.py)。

`_voided_inventory_holding_counts`用一次分组查询读取已作废批次保存的入库数量、日期和销售明细，不改源数据。按创建人当前绑定店铺归属，从入库次日起至售完日（按保存的出库数量及最后销售日判断）或作废日的较早者，标记历史持有区间；部分出库、无销售持续至作废日。作废时间按UTC保存，边界转换为现有核算时区Asia/Shanghai的自然日，入库日仍为0天。本月、上月和年累计分别判断重叠：受影响期间仅存货跌价准备及衍生利润留空并追加warnings；销售转销继续按销售期间规则处理。入库前、售完后、作废后的新月份及其他归属店铺不因本批次持有记录被统一置空；累计期间若包含待核对月份仍留空。这里只圈定待核对区间，不将排除批次所得的0当作已确认的历史费用。

## 截止日库存与跌价准备

2026-10-15追加确认：入库当天0天，销售当天先计提再转销。现行07、09、10、12统一使用[持有期间回放](../../../services/inventory_provision_movements.py)，逐字段/公式见[字段说明](inventory-impairment-fields.md)，实施边界及验证见[变更记录](../../development/2026-10-15-holding-period-impairment.md)。

_load_inventory_provision_data一次读取批次、规则和逐笔FIFO明细，在内存按天回放；同一请求的数据库会话按截止日复用结果。先加入当日入库/规则，分配实际共享安全库存，只增加当日新比例，再按已保存批次明细转销。新品日增0.5%、稳健1%、每个整数数量层最多90%；保护已形成准备，后到货不重置旧批日期或补算旧日保护。

异常批次自身从异常销售日开始标记待核对；向同商品其他批次传播须按当天规则判断：仅当稳健安全库存为正，且原始异常批次按记录仍在库、异常已发生但尚未到记录入库日，或当日又发生异常销售时，才影响当天库龄大于0的其他在库批次。后来启用安全库存不倒改此前健康月份；原始异常批次售完后不预先污染后来入库批次，但若其又出现超量销售，异常当天仍须核对。因共享安全库存形成的准备未知继续保留，但它自身不成为新的数量异常源。相关空值仍不以0代替，见[持有期间回放](../../../services/inventory_provision_movements.py)的`replay_inventory_provisions`。

回放完成后，`ProvisionReplay`按批次和日期预汇总增提、转销，并建立金额前缀和及独立未知次数索引。任意左闭右开期间查询用日期二分定位，不对每个批次反复扫描全局流水；期间含未知金额或未知转销时仍返回null，其他期间不被污染。回放结果及原始事件列表构建后按只读方式复用。

期初+本月总计提−本月销售转销=期末准备；账面=现存成本−期末准备。保留现存库存本月计提以区分指标；售完期末余额为0，本月总计提/转销仍可能非0。按同一回放重建上月账面，不读写或补建快照。

全局计算共享安全库存后，按原店铺范围过滤输出；独立存货仍为全局，财务附件非管理员按绑定店铺。销售早于入库、超量出库等相关金额返回null；按列传播到SKU/合计。规则推定和保存成本不一致在备注说明，不能把估算当作完整历史。

批次日期更正后，如果报告截止日在新入库日前但该批次已有截止日前销售，07 明细仍保留该异常批次：当日现存数量按回放为 0，已保存销售数量与成本继续展示，销售转销等无法确认的金额为 null，并在备注标出日期待核对。没有截止日前销售的未来批次不进入该报表；按店铺查看时仍按原创建人当前绑定店铺过滤。依据：[reports.py](../../../routers/reports.py) 的 `_load_inventory_provision_data`、`_load_inventory_impairment_report_rows`。

## 店铺损益及期间

独立结算调整由[financial_facts.py](../../../services/financial_facts.py)的unlinked_settlement_events读取：排除直接/组件已关联出库的结算、排除待确认的普通正数量订单，纳入退款、赔付等不出库事件。按结算日期→订单日期→导入日期归月；导入日期兜底时提示核对，原销售仍按sold_at。净商品额及原差额费用沿用保存值和汇率，赔付仍按既有绝对值费用口径，不恢复库存或冲改原FIFO成本。销售月度/列表、09/10/12及Excel共享同一来源，未确定组合份额归产品线未分配组。

_month_periods 定义 current（本月）、previous（上月）、ytd（当年1月到本月末），均采用左闭右开区间；report_month 必须该月第一天。自动项与来源：

| 项目 | 实际来源/算法 |
| --- | --- |
| 商品销售收入 | 通过 _sale_import_context 还原净商品收入并乘固化汇率；手工销售以CNY处理 |
| 商品采购成本 | 按原批次 purchase_price 计算权重，从该笔已保存FIFO成本中分配 |
| 头程尾程物流成本 | 按批次 shipping_cost+last_mile_cost 及原始数量计算权重，从该笔已保存FIFO成本中分配 |
| 入库其他成本 | 按批次 other_cost 及原始数量计算权重，从该笔已保存FIFO成本中分配，按销售日计入期间 |
| 其他直接成本 | 销售来源其他费用/平台费按汇率换算 |
| 存货跌价准备 | 对应期间每天实际新增准备合计 |
| 销售转销跌价准备 | 已售商品对应准备抵减营业成本，不改保存的FIFO成本 |
| 房租+水电+网费 | OA 指定部门租金/电费，按当前启用店铺数均分 |
| 分摊人事财务 | OA 同名非零组件，按当前启用店铺数均分 |
| 人员薪资 | OA 部门名精确匹配店铺名；已保存人工值优先 |

批次数量/成本经历史编辑更正后，原FIFO单价不改写；_fifo_cost_components通过base_cost_components读取cost_basis冻结的原构成，再叠加各类差额。不能改用当前数量和最近目标费用重新分配旧FIFO成本，否则会重复或错配成本。当前查询追溯原销售月，旧FinancialReportVersion.payload保持原值；规则及结构前提见[库存流程](../inventory/workflow.md#编辑与删除)。

关税、本地物流、代发、运费/其他收入、广告、税费等人工项按报表JSON保存；自动项与公式项不允许通过manual_values覆盖，不支持的键被忽略。PUT默认update_scope=all，仍完整替换manual_values/remarks；页面显式使用current，仅替换本月人工列并在metadata标记monthly。原比较值保留存储；读取时上月取上月记录的current，年累计按当年各月current汇总，OA薪资按月缺省/覆盖后汇总。旧all模式显式比较值保持兼容，缺失比较值才推导，未提交本月项清空为null。已有报表行锁保护读取及合并；响应同时提供最终计算值value和实际保存的manual_value，页面只用后者填入输入框，OA默认薪资显示为占位值，留空提交null并继续随OA重算。备注始终完整替换；空人工薪资可以回落到OA默认。UI只编辑本月列，API/Excel仍含三个期间，具体契约见[损益API](api.md#损益保存契约)。

页面加载时清空旧报表并禁用保存；仅最新请求且店铺/月与控件一致的响应可展示。保存绑定已加载报表的店铺和月份，禁止重复提交；保存中切换条件会等待其结束再查询，旧保存成功响应不会覆盖新选择，保存失败始终提示原月份，避免未保存的修改静默丢失。会话过期使待处理报表请求失效。依据：[运行模板](../../../templates/index.html) 的 loadStoreProfitLoss、saveStoreProfitLoss、resetStoreProfitLossState；[页面模拟检查](../../../tests/profit_loss_page_checks.cjs)同时覆盖根目录副本。

店铺损益期间跌价费用取总计提，营业成本减销售转销；本月、上月、年累计分别汇总。跨店或缺失店铺归属且有非零转销、或历史时序异常时，不猜测归属：受影响准备/转销及衍生利润留空，通过API warnings、页面提示和Excel备注说明。其他可确定的收入及原始成本仍展示。普通空人工科目依旧按原约定参与计算，不能把待核对的自动金额当0。

1月读取上年12月销售/费用以覆盖上月比较，不把仅查询当年数据所得的空成本与上月转销相减。OA读取区间同步覆盖所有核算期间。产品线按相同销售成本明细扣除已确认转销，归属不明时该期间成本及毛利/汇总留空。

营业收入 = 商品+运费+其他收入；营业成本 = 采购+头尾程+入库其他成本+关税+本地物流+代发+其他直接；营业成本再减已确认销售转销；毛利 = 收入−成本；毛利率 = 毛利÷收入（收入0时空）。营业利润从毛利依次扣税金、销售/管理/研发/财务费用、资产和信用减值，净利润再加减营业外收支与所得税。

2026-10-16起，批次other_cost以“入库其他成本”自动项纳入09、10、12，原销售FIFO成本不改写。每条销售明细先取已保存的数量×单件成本作为总额，再按批次采购、物流、其他三部分原始金额比例拆分；最后一个非零科目承接除法尾差，使三项之和等于保存的FIFO成本。原始三项全为0但保存成本非0的异常历史暂归采购成本，需财务核对。例如100件×采购单价10元、整批其他成本1000元，售10件：采购100元+入库其他100元=成本200元。产品线直接按同一已保存明细成本汇总。此项与销售侧“其他直接成本”独立；如果历史上将同笔入库费用人工填入关税/物流/代发等科目，应由财务核对重复，不自动清空历史人工值。缺失/无效历史汇率时，对应期间自动收入、销售费用、相关利润及Excel合计留空并提示；已保存的人民币FIFO成本可继续核对。产品线的未知收入/费用同样传播，不能显示部分数据计算的毛利。实际历史费用分类、跨表勾稽及缺失数据影响仍待财务核验。

依据：[reports.py](../../../routers/reports.py) 的 STORE_PROFIT_LOSS_ROWS、_store_profit_loss_auto_values、_build_store_profit_loss_values、update_store_profit_loss。

## 产品线、跨店汇总与 Excel

产品线通过销售店铺/本地商品、来源平台 SKU 和销售日期匹配有效 StoreProduct；无来源 SKU、匹配失败或产品线冲突进入未分配组。手工销售通常无来源平台 SKU，需要关注该组。每店运费/其他收入以及人工关税/本地物流/代发按该店各线销售收入比例分摊，不能跨店混分；期间收入合计0时不分摊。

产品线批次成本直接使用实际FIFO明细保存的数量×单件成本，包含采购、头尾程及入库其他成本，再加销售侧费用和分摊成本、减已确认销售转销；与店铺损益三个自动成本科目之和保持一致，不重复加入人工分摊池。

管理员跨店汇总仅包含当前启用店铺，数值来自相同店铺损益计算，合计毛利率是总毛利÷总收入。财务附件中管理员的存货为全局、单店损益为所选店铺、汇总/产品线为启用店铺；非管理员按绑定店铺且不生成第三张跨店汇总。

存货批次 Excel 输出公式及缓存值，通过 _workbook_bytes_with_formula_cache 改写工作簿 XML 的结果缓存；openpyxl 本身不计算公式，追加的 SKU 汇总写已计算数值。财务附件统一输出不等于所有来源已核对，须保留未映射、缺失率和成本分类检查。

依据：[reports.py](../../../routers/reports.py) 的 _product_line_mapping_for_sale、_product_line_profit_data、_allocate_store_profit_loss_to_product_lines、_build_store_profit_loss_summary_sheet、export_financial_attachments；验证入口见[代码映射](code-map.md)。

## 实际成本、费用来源及月度版本

开启财务增强后，销售月成本、库存和持有期间准备加入当前已知补差并追溯原月份；不是以调整单日期过滤历史重算。每店/月/科目选择ledger替换人工项，存在草稿则相关金额/利润null；原人工备选值保留，页面只读显示ledger结果。仅相关科目的比较值受明细来源影响，其他旧人工比较值保留。

FinancialReportVersion保存独立不可变payload，显式保存新版本；它与AccountingPeriod自动快照不同。旧版导出只读payload，当前导出仍是实时重算；平台分类/回款不改变已入账差额，核对警示随版本保留。详见[财务增强流程](../financial-control/workflow.md)。
