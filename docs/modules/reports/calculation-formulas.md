### 符号及共同约定

- `D`：存货报告截止日，包含当天全部销售；`M`：D所在月第一天；`P`：上月最后一天。
- `B`：批次入库日期；`Q0`：批次原始入库数量；`C`：批次保存的单件到仓成本；`Q_t`：t日销售后的批次库存。
- `q_tj`、`r_tj`：t日单日规则算法拆出的第j部分数量与累计比例。批次内不同部分可能有不同的累计比例。
- `Σ`：在指定批次、日期、店铺或产品线范围内求和；比例在接口中为小数，例如0.20显示为20.00%。
- 金额使用Decimal计算，数据库金额字段按各自DECIMAL精度保存。报表通常显示两位金额和两位百分数；中间计算不强制先舍入到两位。
- 没有统一的“空值一律为0”规则：损益参与加减的空值按0；毛利率分母为0时为空；存货比较值未知时保留为空；销售月度缺汇率时部分金额整月为空。

依据：[reports.py](../../../routers/reports.py) 的 `_decimal_or_zero`、`_month_periods`，以及[运行模板](../../../templates/index.html)的 `reportMoney`、`reportPercent`。

## 成本与销售金额的基础公式

后续各张报表使用以下基础金额，但它们的成本分类并不完全相同。

| 基础项目 | 当前公式与条件 |
| --- | --- |
| 入库采购单价 | 明确填写采购总金额时：采购总金额÷原始入库数量；否则按入库接口的采购单价/已有批次规则确定。 |
| 单件到仓成本 `C` | 采购单价＋（整批头程运费＋整批尾程运费＋整批其他费用）÷原始入库数量。报表读取保存的 `inventory_batches.unit_cost`。 |
| 原始入库成本金额 | `Q0×C`。包含分摊物流/其他费用，不仅是采购总金额。 |
| 单笔FIFO销售成本 | `Σ(本笔成本明细数量×成本明细保存的单件成本)`；销售时保存为 `sales.total_cost`。 |
| 手工销售净商品收入 | 销售单价×销售数量；币种按CNY、汇率按1处理。 |
| 导入净商品收入（原币） | 结算记录保存的净商品销售额，按对应销售分摊比例分配；不另外用售价、折扣、退款字段重新计算同一净额。 |
| 导入其他费用（原币） | 净商品销售额−结算总金额；“物流赔付”“平台赔付”取该差额绝对值。 |
| 人民币净商品收入 | 对应销售的原币净商品收入×保存的历史人民币汇率。 |
| 人民币其他费用 | 对应销售的原币其他费用×保存的历史人民币汇率。 |

组合销售的金额分摊也属于收入来源的一部分：

```text
组件出库数量 = 来源销售数量 × 每次销售的组件数量
导入时组件分摊比例 = 组件FIFO成本 ÷ 所有组件FIFO成本
若总成本为0，退回按组件出库数量占比分摊

报表还原结算金额时：
销售权重 = 保存的销售单价 × 销售数量
分摊比例 = 销售权重 ÷ 同一结算记录相关销售的权重合计
若权重合计不大于0，退回按关联分摊数量占比；数量也无有效合计时均分
对应销售净商品收入 = Σ(结算净商品销售额 × 该销售分摊比例)
对应销售其他费用 = Σ(结算差额费用 × 该销售分摊比例)
```

报表使用关联结算的历史汇率，不重新查询当天汇率。只有关联到已生成销售的结算数据进入这里的收入/费用链路；待确认记录和未关联销售的独立结算费用不会自动完整纳入这些损益项目。

依据：[batches.py](../../../routers/batches.py) 的 `_resolve_purchase_values`、`_calc_unit_cost`；[fifo.py](../../../services/fifo.py) 的 `fifo_sell`；[sales.py](../../../routers/sales.py) 的 `_component_allocation_shares`、`_other_expense_from_row`、`_sale_import_context`。更完整导入规则见[销售流程](../sales/workflow.md)。

## 存货批次公式

07包含全部已到货批次，按自然日重放真实数量层。入库当天0天，销售当天先计提再出库转销。完整23个显示字段及24个API字段来源见[字段说明](inventory-impairment-fields.md#页面23列完整对照)。

| 项目 / 字段 | 公式 |
| --- | --- |
| 库龄 age_days | max(0,D−B)，以自然日计。 |
| 原始入库成本 original_inventory_amount | Q0×C。 |
| 累计销售成本 sold_cost_amount | Σ(截至D的FIFO明细数量×明细保存单价)。 |
| 现存数量 quantity | 原始数量减截至D有效销售扣减；异常时不静默修复事实。 |
| 现存成本 inventory_amount | 当前剩余数量×批次单价。 |
| 期末计提数量 provision_quantity | 回放后累计比例大于0的现存整数数量层之和；异常时空。 |
| 累计比例 impairment_rate | Σ(各现存层数量×累计比例)÷期末计提数量；分母0时0。 |
| 期末准备 impairment_amount | C×Σ(各现存数量层×其已形成累计比例)。 |
| 现存本月计提 monthly_impairment_amount | C×Σ(现存层数量×该层本月增加的比例)。 |
| 期初准备 opening_impairment_amount | 同一回放服务在上月末的准备余额，本月新批为0。 |
| 本月总计提 monthly_total_impairment_amount | Σ(本月每天实际新增准备)，含已售商品售出前的本月增提。 |
| 本月销售转销 monthly_writeoff_amount | Σ(本月各FIFO销售明细对应层数量×销售时已形成比例×批次单价)，可能含期初准备。 |
| 账面 book_value | 现存成本−期末准备；已售完期末为0。 |
| 与上月账面差 book_value_difference | 本期账面−同一回放所得上月账面；可能含销售/入库变化，未知时空。 |

```text
每日新增加比例：新品0.5%；稳健商品非保护数量层1%；达到90%的层新增为0
每日新增准备 = Σ(当日计提层数量×单价×min(日增率,90%−原比例))
期初准备 + 本月总计提 − 本月销售转销 = 期末准备
期末账面 = 剩余成本 − 期末准备
```

当日先加入已到货批次、应用生效规则和安全库存，再计提并按销售时间/销售id/明细id转销。安全库存优先保护最新批次及批内靠后的整数层；层内原准备保留。批内销售从较早层扣减，数量不作小数分摊。规则历史随当天生效，不因后来新入库改变已经发生的保护和计提。

固定规则新品期末仍为`剩余数量×C×min(库龄×0.5%,90%)`。稳健商品涉及保护变化时，不能把当前库龄和当前安全库存直接回算全部历史。历史规则缺失/首条记录晚于入库有推定和备注；销售早于入库、超量等异常相关金额为空，并传播对应合计。

### 已确认例子

满30天例子：8月31日入库100件×10元，9月10日售10件（满10天），9月20日售30件（满20天），9月30日满30天：

```text
销售转销 = 10×10×5% + 30×10×10% = 35
期末准备 = 60×10×15% = 90
本月总计提 = 90−0+35 = 125
账面 = 60×10−90 = 510
```

9月1日入库、仍在满10/20天时销售，9月30日为29天：总计提122、转销35、期末87、账面513。原入库100件×10元、售40剩60、库龄40天时，固定新品期末准备120、账面480，仍成立。

跨月时转销含期初：期初准备100，期间总计提40、销售转销50，期末90；其中现存库存本月计提30，并非40或50。更多来源和边界见[字段说明](inventory-impairment-fields.md)。

依据：[持有期间服务](../../../services/inventory_provision_movements.py)、[reports.py](../../../routers/reports.py)的_load_inventory_provision_data、_load_inventory_impairment_report_rows；回归见[test_inventory_provision_movements.py](../../../tests/test_inventory_provision_movements.py)、[test_provision_reporting.py](../../../tests/test_provision_reporting.py)。

## 存货SKU及全表合计

| 项目 | 汇总公式 |
| --- | --- |
| 入库批次数 `batch_count` | 截止日前该内部商品ID的批次数，包含已售完旧批。 |
| 原始入库数量、累计销售数量、现存数量、期末计提数量 | `Σ(同商品所有纳入批次的对应数量)`。 |
| 原始入库成本、累计销售成本、现存库存成本 | `Σ(同商品所有纳入批次的对应成本金额)`。 |
| 期初/期末准备、本月总计提/转销、现存本月计提 | `Σ(各批次按自身单价、日期、剩余库存算出的对应金额)`。 |
| 账面价值 | `Σ(批次现存库存成本−批次期末累计准备)`。 |
| 账面价值差额 | 所有批次基准已知时为 `Σ(各批次账面差额)`；任一基准未知则该SKU差额为空。 |
| 页面/Excel全表合计 | 对对应数量和金额列求和；差额列有未知行时，差额合计为空。 |

不合计单价、库龄、比例或状态。新到货批次保留自己的成本与日期，不用最新单价改算旧批；全局SKU汇总按内部商品ID合并，可跨店展示店铺名称。

下面是核对式，成立条件是历史明细保存单价与该批次单价一致、流水完整且没有超扣：

```text
原始入库数量−累计销售数量 = 现存库存数量
原始入库成本−累计销售成本 = 现存库存成本
```

它们不是当前07账面价值公式。数据来源不同导致不相等时，不能直接改写历史成本来强行对齐。

依据：[reports.py](../../../routers/reports.py) 的 `_summarize_inventory_impairment_rows`、`_build_inventory_impairment_summary_sheet`；[运行模板](../../../templates/index.html)的 `inventoryReportTotals`。

## 店铺损益全部项目

下表完整列出09表的36个科目。公式对本月、上月、本年累计三个期间分别计算；“人工”项目本身没有自动推算公式。每条销售成本明细的已保存FIFO金额记为`S=明细数量×明细保存单件成本`；批次采购、头尾程和其他成本按同数量算原始分摊金额`P0/L0/O0`。三项原始和大于0时，按`P0:L0:O0`比例分配`S`，最后一个原始金额非0的科目承接除法尾差；三项和始终等于`S`。原始三项全为0但`S`非0的异常历史暂归采购科目，需核对原始成本构成。实现见[成本拆分函数](../../../routers/reports.py)的`_fifo_cost_components`。

自动项、公式项不能被 `manual_values` 覆盖。人工金额的本月/上月/年累计是当前核算月份报表JSON中保存的三个值，系统不会自动把其他月份报表的人工“本月金额”累加成年累计。页面仅保存本月，保留已有人工比较值；人员薪资未被人工填写时，页面显示OA默认金额占位但提交null，继续随OA重算。默认API完整替换行为和current范围见[损益保存契约](api.md#损益保存契约)。空的人工项参与加减时按0，人员薪资有上述OA回落规则。

依据：[reports.py](../../../routers/reports.py) 的 `STORE_PROFIT_LOSS_ROWS`、`_build_store_profit_loss_values`、`_store_profit_loss_auto_values`、`get_store_profit_loss`。


自动准备/转销因历史时序或店铺归属待核对时为null，相关成本、毛利或净利润按依赖关系留空，并输出warnings；不套用普通空人工科目按0的规则。

### 损益期间

`report_month`必须为所选月份第一天，三个期间均左闭右开：

| 期间 | 日期范围 |
| --- | --- |
| 本月 `current` | 本月1日00:00至下月1日00:00之前。 |
| 上月 `previous` | 上月1日00:00至本月1日00:00之前。 |
| 本年累计 `ytd` | 当年1月1日00:00至下月1日00:00之前。 |

销售按 `sold_at`归期间，OA费用按申请日期归期间。页面只显示本月；接口和09 Excel包含三个期间。存货截止日D不把09损益的本月范围截断为D，当月的未来销售日期若已经保存，仍可能进入月度计算。1月的销售和OA基础查询已覆盖上年12月，以包含上月比较；真实历史完整性见[待验证事项](#待验证事项与当前实现差异)。

### 损益的存货跌价准备

定义 对应期间使用同一持有期间回放服务：

```text
本期跌价费用 = Σ(本期每天实际新增准备)
本期销售转销 = Σ(本期销售明细对应已形成准备)
营业成本 = 原有各成本科目合计 − 本期销售转销
资产减值损失 = 本期跌价费用
```

例如商品原始销售成本400、本期计提125、转销35：净销售成本365，不能仍扣400再扣125而忽略转销。库存和销售原始成本不改写。

批次归属仍来自创建人当前绑定，销售归属可能不同。跨店或缺失归属且转销非0时，不自动选择费用承担店铺，受影响期间准备/转销和利润留空；同店明确归属按上述公式。1月查询覆盖上年12月，保证上月销售成本、转销和OA费用在相同期间。

依据：[reports.py](../../../routers/reports.py)的_store_provision_financial_values、_store_profit_loss_auto_values、_build_store_profit_loss_values。

### OA费用公式及筛选

```text
房租水电网费默认金额 = Σ(有效办公明细的租金、电费)÷当前启用店铺数
分摊人事财务默认金额 = Σ(同名组件的非零金额)÷当前启用店铺数
人员薪资默认金额 = Σ(工资明细中部门名称=店铺名称的金额)
```

只读取指定流程、未删除、状态COMPLETED且结果同意/通过的单据，以申请日期归期间。办公项目还筛选固定部门；薪资按部门名与店铺名精确匹配。启用店铺数量为查询时的数量，不是历史月份冻结数量；没有启用店铺时不做均分。OA配置缺失返回无数据；配置完整但查询失败会抛错。

依据：[oa_office_expenses.py](../../../services/oa_office_expenses.py) 的 `_office_space_total`、`_china_salary_totals`、`_shared_admin_total`、`_approved_forms_by_expense`及三个按申请日期汇总函数。

## 跨店损益汇总公式

10表只在管理员财务附件中生成，对当前启用店铺的同一个核算月“本月金额”汇总，科目沿用09表。

| 项目 | 公式 |
| --- | --- |
| 各店铺科目金额 | 该店铺09表对应科目的本月计算值。 |
| 各金额科目合计 | `Σ(各启用店铺对应科目的本月金额)`。 |
| 毛利率合计 | `Σ(各店本月毛利)÷Σ(各店本月营业收入)`；总收入为0时为空。 |
| 占比 | `该科目合计÷所有店铺本月营业收入合计`；总收入为0时为空。 |
| 毛利率行的占比 | 留空，不再计算“毛利率的占比”。 |
| 店铺数量 | 本次纳入汇总的启用店铺数。 |

“占比”的分母统一为营业收入合计，包括成本、利润等科目；不是各店占比，也不是费用科目占营业成本。各店毛利率不相加、不简单平均。普通空人工科目仍按原约定处理；待核对的准备/转销、衍生成本及利润保持空，合计和占比同步留空，避免不完整加总。

依据：[reports.py](../../../routers/reports.py) 的 `_build_store_profit_loss_summary_sheet`、`export_financial_attachments`。

## 产品线毛利公式

产品线首先按店铺、内部商品、来源平台SKU及销售日期的有效映射确定归属。缺少来源SKU、无法匹配或冲突的销售进入“未分配产品线”，不根据名称猜测。使用与09相同的本月/上月/年累计期间。

### 分摊与成本构成

先计算每个店铺、每条产品线、每个期间的商品净销售收入 `R_s,l`：

```text
该店该线分摊比例 w_s,l = R_s,l÷Σ(该店各线商品净销售收入)
待分摊收入 = 该店人工运费收入＋人工其他收入
待分摊成本 = 该店人工关税及进口税费＋人工本地物流配送成本＋人工代发成本
该线分摊收入 = 待分摊收入×w_s,l
该线分摊成本 = 待分摊成本×w_s,l

产品线期间收入 = 商品净销售收入人民币＋分摊收入
产品线期间成本 = Σ(该线销售明细数量×明细保存单件成本)＋销售关联其他费用人民币＋分摊成本−已确认销售转销准备
```

分摊按各店各期间分别做，再跨店加总，不把全部店铺金额先混合分摊；“未分配产品线”的收入也参与该店占比。该店该期间商品收入合计为0时不分摊，不转为均分。分摊读取当前核算月报告JSON对应期间的人工值。

产品线按同一销售明细抵减已确认转销；未确认归属/金额的期间成本、毛利及合计留空。这里计算毛利，未扣人员薪资、广告、管理费用、存货跌价、税金及所得税等损益后续项目。每条明细已保存FIFO成本包含入库其他成本，并等于09三个自动入库成本科目之和；销售侧其他费用另计。历史人工录入过同笔费用时需财务核对重复。

依据：[reports.py](../../../routers/reports.py) 的 `_product_line_mapping_for_sale`、`_allocate_store_profit_loss_to_product_lines`、`_product_line_profit_data`、`PRODUCT_LINE_ALLOCATED_REVENUE_KEYS`、`PRODUCT_LINE_ALLOCATED_COST_KEYS`。

### 页面及Excel各列

| 列 | 项目 / 字段 | 公式 |
| --- | --- | --- |


## 自动快照公式与07表的区别

自动月末快照保存的是该日期**现存库存**及准备余额：

```text
快照库存数量 = 原始入库数量−截至月末FIFO出库数量（最低0）
快照库存金额 = 快照库存数量×批次单价
快照准备金额 = 批次单价×月末单日规则算法的跌价折算数量
快照账面价值 = 快照库存金额−快照准备金额
```

按上面的100件例子，9月末剩60件：若来源与规则一致，快照和07均为现存成本600、期末准备120、账面480。快照持久化不覆盖，07动态重算；后续补录/撤销、规则或安全库存保护变化可能造成差异，不能直接用旧快照替换新口径期初。

快照保存后不自动覆盖；07当前不读取/补建快照，07与损益共用持有期间回放服务，快照仍为原静态规则算法。这里仅静态列公式，未触发快照生成。

依据：[accounting_periods.py](../../../services/accounting_periods.py) 的 `_snapshot_rows`、`create_period_snapshot`、`ensure_period_snapshot`。
