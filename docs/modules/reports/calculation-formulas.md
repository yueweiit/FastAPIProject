### 符号及共同约定

- `D`：存货报告截止日，包含当天全部销售；`M`：D所在月第一天；`P`：上月最后一天。
- `B`：批次入库日期；`Q0`：批次原始入库数量；`C`：批次保存的单件到仓成本；`Q_t`：t日销售后的批次库存。
- `q_tj`、`r_tj`：t日单日规则算法拆出的第j部分数量与累计比例。批次内不同部分可能有不同的累计比例。
- `Σ`：在指定批次、日期、店铺或产品线范围内求和；比例在接口中为小数，例如0.20显示为20.00%。
- 金额使用Decimal计算，数据库金额字段按各自DECIMAL精度保存。报表通常显示两位金额和两位百分数；逐日计算不会每天先舍入到两位。
- 没有统一的“空值一律为0”规则：损益参与加减的空值按0；毛利率分母为0时为空；存货比较值未知时保留为空；销售月度缺汇率时部分金额整月为空。

依据：[reports.py](../../../routers/reports.py) 的 `_decimal_or_zero`、`_month_periods`，以及[运行模板](../../../templates/index.html)的 `reportMoney`、`reportPercent`。

## 成本与销售金额的基础公式

后续各张报表使用以下基础金额，但它们的成本分类并不完全相同。

| 基础项目 | 当前公式与条件 |
| --- | --- |
| 入库采购单价 | 明确填写采购总金额时：采购总金额÷原始入库数量；否则按入库接口的采购单价/已有批次规则确定。 |
| 单件到仓成本 `C` | 采购单价＋（整批头程运费＋整批尾程运费＋整批其他费用）÷原始入库数量。报表读取保存的 `inventory_batches.unit_cost`。 |
| 原始入库成本金额 | `Q0×C`。包含分摊物流/其他费用，不仅是采购总金额。 |
| 单笔FIFO销售成本 | `Σ(本笔成本明细数量×成本明细保存的单件成本)`；销售时保存为 `sales.total_cost`。 |
| 手工销售净商品收入 | 销售单价×销售数量；币种按CNY、汇率按1处理。 |
| 导入净商品收入（原币） | 结算记录保存的净商品销售额，按对应销售分摊比例分配；不另外用售价、折扣、退款字段重新计算同一净额。 |
| 导入其他费用（原币） | 净商品销售额−结算总金额；“物流赔付”“平台赔付”取该差额绝对值。 |
| 人民币净商品收入 | 对应销售的原币净商品收入×保存的历史人民币汇率。 |
| 人民币其他费用 | 对应销售的原币其他费用×保存的历史人民币汇率。 |

组合销售的金额分摊也属于收入来源的一部分：

```text
组件出库数量 = 来源销售数量 × 每次销售的组件数量
导入时组件分摊比例 = 组件FIFO成本 ÷ 所有组件FIFO成本
若总成本为0，退回按组件出库数量占比分摊

报表还原结算金额时：
销售权重 = 保存的销售单价 × 销售数量
分摊比例 = 销售权重 ÷ 同一结算记录相关销售的权重合计
若权重合计不大于0，退回按关联分摊数量占比；数量也无有效合计时均分
对应销售净商品收入 = Σ(结算净商品销售额 × 该销售分摊比例)
对应销售其他费用 = Σ(结算差额费用 × 该销售分摊比例)
```

报表使用关联结算的历史汇率，不重新查询当天汇率。只有关联到已生成销售的结算数据进入这里的收入/费用链路；待确认记录和未关联销售的独立结算费用不会自动完整纳入这些损益项目。

依据：[batches.py](../../../routers/batches.py) 的 `_resolve_purchase_values`、`_calc_unit_cost`；[fifo.py](../../../services/fifo.py) 的 `fifo_sell`；[sales.py](../../../routers/sales.py) 的 `_component_allocation_shares`、`_other_expense_from_row`、`_sale_import_context`。更完整导入规则见[销售流程](../sales/workflow.md)。

## 存货批次公式

07表按截止日前全部到货批次计算，包含已售完旧批。它按2026-10-12确认的逐日金额累计规则计算；账面价值保留负数。

| 页面项目 / 接口字段 | 公式 |
| --- | --- |
| 已入库天数 `age_days` | `max(0, D−B)`，以自然日计，入库当天为0。 |
| 原始入库数量 `original_quantity` | 批次保存的 `Q0`，不会因销售扣减。 |
| 原始入库成本金额 `original_inventory_amount` | `Q0×C`。 |
| 累计销售出库数量 `sold_quantity` | `Σ(本批次、销售日期≤D的FIFO成本明细数量)`。 |
| 累计销售出库成本 `sold_cost_amount` | `Σ(上述明细数量×明细保存单价)`。不使用后来入库的新批次单价。 |
| 每天销售后的数量 `Q_t` | `max(0, Q0−Σ(本批次销售日期≤t的FIFO明细数量))`。 |
| 现存库存数量 `quantity` | `Q_D`，由历史流水重建，不直接读取当前 `remaining_quantity`。 |
| 当日计提数量 `provision_quantity` | 单日规则算法中，累计比例大于0的现存数量之和，即 `Σ(q_Dj，其中r_Dj>0)`；历史规则可能使安全库存内的数量仍保留以前累计比例。无已生效历史规则的兼容分支按该分支的计提数量返回。 |
| 现存库存成本金额 `inventory_amount` | `C×Q_D`。 |
| 当日累计比例 `impairment_rate` | `Σ(q_Dj×r_Dj)÷当日计提数量`；计提数量为0时为0。 |
| 当天跌价金额 `A_t`，中间值 | `C×Σ(q_tj×r_tj)`。先扣当天全部销售，再计算。 |
| 累计跌价（逐日累计） `impairment_amount` | `Y_D=Σ(A_t，B次日至D)`。售完后停止新增，售前金额保留。 |
| 本月跌价（逐日累计） `monthly_impairment_amount` | `Σ(A_t，M至D)`，只包含已到货后的有效日期。包含本月已售商品售前的金额。 |
| 账面价值 `book_value` | `V_D=Q0×C−Y_D`；不再减累计销售成本，不按0截断。 |
| 上月末账面价值，中间值 | 上月已到货批次：`V_P=Q0×C−Y_P`；本月新增批次：`V_P=0`。`Y_P`按相同逐日公式算至P。 |
| 与上月末账面价值差额 `book_value_difference` | `V_D−V_P`。方向是当前减上月；比较值未知时为空。 |
| 上月末库存，中间值/Excel备注 | 上月已到货批次：`max(0, Q0−Σ(销售日期≤P的本批明细数量))`；本月新增批次为0。 |

对于上月已到货且原始成本未变化的同一批次：

```text
与上月末账面价值差额 = −本月逐日累计跌价
```

本月新增批次的差额包含该批原始入库成本，不能直接用全表账面差额代替本月跌价。

条件判断顺序如下：

| 状态 | 条件 |
| --- | --- |
| 已售完 | 截止日库存为0。 |
| 安全库存内 | 库存非0，且当日计提数量为0。入库当日也可能满足这个代码条件。 |
| 比例达到上限 | 前两项均不满足，且当日累计比例≥90%。 |
| 比例接近上限 | 前三项均不满足，且当日累计比例≥60%。 |
| 正常计提 | 其他情况。 |

店铺、SKU、名称、批次号、入库日期是来源字段，没有另外的数学公式；对应血缘见[逐字段说明](inventory-impairment-fields.md)。

依据：[reports.py](../../../routers/reports.py) 的 `_load_inventory_impairment_report_rows`、`inventory_impairment_report`；[inventory_daily_impairment.py](../../../services/inventory_daily_impairment.py) 的 `daily_accumulated_impairments`。

### 当天累计比例与安全库存

在商品类型、安全库存及规则没有变化的简单场景下：

```text
新品：当天累计比例 = min(库龄×0.5%, 90%)，全部剩余库存参与
稳健：当天累计比例 = min(库龄×1%, 90%)，安全库存以外数量参与
当天跌价金额 = 当天计提数量×批次单价×当天累计比例
```

安全库存是同商品批次共享的数量，按入库日期和批次ID倒序，先保护最新批次：

```text
当前批次保护数量 = min(当前批次剩余数量, 尚未分配的安全库存数量)
尚未分配的安全库存数量 -= 当前批次保护数量
单一稳健规则下的计提数量 = 批次剩余数量−保护数量（库龄>0）
```

有规则历史时，不能把当前商品类型的日增率乘整个库龄。单日算法按规则生效段处理各数量部分：

```text
某规则段有效天数 = max(0,
    min(t次日, 下条规则生效日) − max(本批入库次日, 本条规则生效日))
该段新增比例 = 有效天数×该段日增率
未保护部分累计比例 = min(原累计比例＋该段新增比例, 90%)
保护部分累计比例 = 原累计比例（保留以前金额，不继续增加该段比例）
当日跌价折算数量 = Σ(各部分数量×各部分累计比例)
当日加权比例 = 当日跌价折算数量÷当日计提数量
```

07每天重建该日库存层，再调用上述单日算法。比例上限限制每个部分的累计比例，**不限制逐日金额合计**；达到90%后，仍有计提库存的后续日期继续产生当天金额。规则缺失时有推定/兼容处理，不等于真实历史已补全；单日算法也没有独立的逐件准备转销台账。

依据：[inventory_impairment.py](../../../services/inventory_impairment.py) 的 `batch_impairments`、`_historical_batch_impairments`、`_legacy_batch_impairments`、`_safe_stock_protection`。

### 已确认例子

新品100件，单价10元；2026-08-21入库，第1、2天各卖10件，此后不销售。2026-09-30库龄40天，剩80件：

```text
第1天金额 = 90×10×0.5% = 4.50
第2天金额 = 80×10×1% = 8.00
第3天金额 = 80×10×1.5% = 12.00
……
第40天金额 = 80×10×20% = 160.00
累计跌价 = 4.50＋Σ(80×10×d×0.5%, d=2..40) = 3,280.50
账面价值 = 100×10−3,280.50 = −2,280.50
8月累计 = 220.50；9月本月跌价 = 3,060.00
上月末账面价值 = 1,000−220.50 = 779.50
与上月末账面差额 = −2,280.50−779.50 = −3,060.00
```

来源：[逐日累计回归例子](../../../tests/test_inventory_daily_impairment.py)与[存货字段说明](inventory-impairment-fields.md#财务验收例子)。

## 存货SKU及全表合计

| 项目 | 汇总公式 |
| --- | --- |
| 入库批次数 `batch_count` | 截止日前该内部商品ID的批次数，包含已售完旧批。 |
| 原始入库数量、累计销售数量、现存数量、当日计提数量 | `Σ(同商品所有纳入批次的对应数量)`。 |
| 原始入库成本、累计销售成本、现存库存成本 | `Σ(同商品所有纳入批次的对应成本金额)`。 |
| 累计跌价、本月跌价 | `Σ(各批次按自身单价、日期、每日库存算出的对应金额)`。 |
| 账面价值 | `Σ(批次原始入库成本−批次累计跌价)`。 |
| 账面价值差额 | 所有批次基准已知时为 `Σ(各批次账面差额)`；任一基准未知则该SKU差额为空。 |
| 页面/Excel全表合计 | 对对应数量和金额列求和；差额列有未知行时，差额合计为空。 |

不合计单价、库龄、比例或状态。新到货批次保留自己的成本与日期，不用最新单价改算旧批；全局SKU汇总按内部商品ID合并，可跨店展示店铺名称。

下面是核对式，成立条件是历史明细保存单价与该批次单价一致、流水完整且没有超扣：

```text
原始入库数量−累计销售数量 = 现存库存数量
原始入库成本−累计销售成本 = 现存库存成本
```

它们不是当前07账面价值公式。数据来源不同导致不相等时，不能直接改写历史成本来强行对齐。

依据：[reports.py](../../../routers/reports.py) 的 `_summarize_inventory_impairment_rows`、`_build_inventory_impairment_summary_sheet`；[运行模板](../../../templates/index.html)的 `inventoryReportTotals`。

| 30 | 营业利润 `operating_profit` | 公式 | 毛利−税金及附加−销售费用−管理费用−研发费用−财务费用−资产减值损失−信用减值损失。 |

### 损益的存货跌价准备

定义 `L_s(T)`为店铺s在T日期末，**仍在库商品的准备余额**：

```text
日期末批次数量 = max(0, 原始入库数量−截至该日期销售FIFO明细数量)
批次准备余额 = 批次单价×Σ(日期末各部分数量×各部分累计比例)
L_s(T) = Σ(归属店铺s的批次准备余额)

本月存货跌价准备 = L_s(本月末)−L_s(上月末)
上月存货跌价准备 = L_s(上月末)−L_s(上上月末)
本年累计存货跌价准备 = L_s(本月末)−L_s(上一年12月31日)
资产减值损失 = 对应期间存货跌价准备
```

负的余额差保留，不按0截断。当前先对所有商品库存层分配共享安全库存，再汇总归属该店铺的批次；批次店铺来自创建人当前绑定。这里重新计算各期末余额，不是直接把07逐日累计金额或快照保存金额拿来相减。

用上面的100件例子，且无其他批次、规则变化：

```text
8月末剩余库存准备余额 = 80×10×5% = 40
9月末剩余库存准备余额 = 80×10×20% = 160
09表9月存货跌价准备 = 160−40 = 120
07表9月逐日累计跌价 = 3,060
```

两者不能直接勾稽为相等；完整的准备计提、销售转销、转回会计台账尚需另外确认。

依据：[reports.py](../../../routers/reports.py) 的 `_store_inventory_impairment_totals`、`_store_profit_loss_auto_values`。

## 产品线毛利公式

产品线首先按店铺、内部商品、来源平台SKU及销售日期的有效映射确定归属。缺少来源SKU、无法匹配或冲突的销售进入“未分配产品线”，不根据名称猜测。使用与09相同的本月/上月/年累计期间。

### 分摊与成本构成

先计算每个店铺、每条产品线、每个期间的商品净销售收入 `R_s,l`：

```text
该店该线分摊比例 w_s,l = R_s,l÷Σ(该店各线商品净销售收入)
待分摊收入 = 该店人工运费收入＋人工其他收入
待分摊成本 = 该店人工关税及进口税费＋人工本地物流配送成本＋人工代发成本
该线分摊收入 = 待分摊收入×w_s,l
该线分摊成本 = 待分摊成本×w_s,l

产品线期间收入 = 商品净销售收入人民币＋分摊收入
产品线期间成本 = 商品采购成本＋头程尾程物流成本＋销售关联其他费用人民币＋分摊成本
```

分摊按各店各期间分别做，再跨店加总，不把全部店铺金额先混合分摊；“未分配产品线”的收入也参与该店占比。该店该期间商品收入合计为0时不分摊，不转为均分。分摊读取当前核算月报告JSON对应期间的人工值。

产品线这里计算毛利，未扣人员薪资、广告、管理费用、存货跌价、税金及所得税等损益后续项目。与09相同，采购/物流拆分当前没有把批次 `other_cost` 自动作为该处的一项成本。

依据：[reports.py](../../../routers/reports.py) 的 `_product_line_mapping_for_sale`、`_allocate_store_profit_loss_to_product_lines`、`_product_line_profit_data`、`PRODUCT_LINE_ALLOCATED_REVENUE_KEYS`、`PRODUCT_LINE_ALLOCATED_COST_KEYS`。

## Excel实际单元格公式

当前只有07批次表写入以下行公式，以及数量/金额合计的SUM公式。以第2行为例、报告日2026-10-13说明：

| 列/单元格 | 实际Excel公式 | 含义 |
| --- | --- | --- |
| E2 | `=IF(D2="","",DATE(2026,10,13)-D2)` | 固定报告日期减入库日期，不用TODAY。 |
| H2 | `=IF(OR(F2="",G2=""),"",F2*G2)` | 单价×原始入库数量。 |

## 自动快照公式与07表的区别

自动月末快照保存的是该日期**现存库存**及准备余额：

```text
快照库存数量 = 原始入库数量−截至月末FIFO出库数量（最低0）
快照库存金额 = 快照库存数量×批次单价
快照准备金额 = 批次单价×月末单日规则算法的跌价折算数量
快照账面价值 = 快照库存金额−快照准备金额
```

按上面的100件例子，9月末快照库存金额800，准备160，账面640；07逐日累计表的原始成本1,000，累计3,280.50，账面−2,280.50。两者的账面值含义不同。

快照保存后不自动覆盖；07当前不读取/补建快照，损益准备余额也由其自己的库存重算函数取得。这里仅静态列公式，未触发快照生成。

依据：[accounting_periods.py](../../../services/accounting_periods.py) 的 `_snapshot_rows`、`create_period_snapshot`、`ensure_period_snapshot`。
