# 操作日志

统一入口为主导航“操作日志”，仅管理员可见。查询接口只读；汇总已有批次修改/作废、库存盘点版本、销售导入/手工补录及撤销、启用时的财务审计。另由可选的business_operation_logs记录新发生的业务变更，需准备结构并启用FIFO_OPERATION_AUDIT_ENABLED。不开启时兼容旧业务，若表已存在仍可读取历史。批次列表移除独立“日志”按钮，旧批次查询接口仅作为管理员只读兼容入口；不删除历史日志，不回填旧操作，不改写库存、销售、成本或旧报表版本。

## 新增业务留痕

| 模块 | 捕获入口与内容 |
| --- | --- |
| 商品 | 新增、修改/图片/类型/安全库存、删除、批量新增；逐商品保存前后值 |
| 账号 | 创建、启停、角色、店铺绑定、删除、密码重置和本人改密；只记录已设置/已变更标记，不记录密码或哈希 |
| 财务主数据 | 店铺、产品线、店铺商品映射、平台SKU映射及组件增删改；一次保存涉及多组件时共用group_id |
| 新批次 | 入库数量、四项成本、单号和日期；后续更正/作废/归属仍复用BatchChangeLog |
| 销售 | 旧手工销售接口创建、待确认处理的来源状态及组件分配；导入/补录/撤销沿用已有历史，不重复新增整批审计 |
| 报表 | 损益表人工数据、备注、元数据保存前后值；财务增强凭证等继续复用FinancialAuditEvent |

来源为[services/business_audit.py](../../../services/business_audit.py)的路由policy和模型FIELDS白名单。只记录已提交的业务状态变化，不是所有HTTP请求或安全登录日志；读取、导出、导入预览、登录/退出及会话刷新不新增审计，无变化保存不产生日志。图片只保存路径，不存文件内容。待确认原始raw_data、请求体及认证字段不保存。已有导入计数仍是可更新的业务历史，不能当作不可变审计。

审计在原业务事务提交前读取实际落库值，金额保留数据库Decimal精度。同一对象在一次事务内多次flush合并为最终变更；保存点回滚不留失败组件。审计失败则业务一并回滚（含FIFO库存、销售和成本明细）；不以虚假成功继续提交。独立提交的后续响应/OA计算失败不撤销已经提交的业务及日志。日志保存操作人ID/用户名/角色和对象标签快照，不建删除级联外键；删除账号、商品后保留日志。未加载的修改前值明确标为“旧值未记录”，不猜测为零或空值。

待确认重试替换组件时，复用此前按序锁定的分配对象，通过ORM删除并先flush，再新增替代组件，避免来源/商品唯一键冲突。旧组件记录action=delete、完整before_values及空after_values，新组件记录process_pending，共用group_id；仅删除无替代组件时，也从原结算来源确定店铺，不能依赖管理员是否绑定店铺。销售/损益日志的归属以业务对象或组件来源为准，来源为空保持为空，仅管理员可见，不套用操作者店铺。失败时删除、FIFO和新增日志一并回滚。审计依赖ORM事务事件，后续白名单对象的批量SQL需另行显式捕获，不能假定自动覆盖。

## 查看方式

按分类、操作类型、原记录日期、用户名、店铺、商品名称/SKU/批次号/文件名及同次操作编号筛选；分页20/50/100条，不一次加载全量历史。同次操作编号可从详情复制，用于追查一次批量保存的对象，权限不会扩大。店铺筛选只匹配保存的store_id，共享商品/批次/盘点没有单店归属。新商品日志的SKU/名称优先读取自身前后快照，其他关联商品/店铺显示当前名称；店铺已删除时显示原ID及名称未记录，不误标共享。旧来源的用户名/店铺名称也可能是当前主数据，不宣称全部为当时名称快照。

列表显示模块色标、操作、关联编号、商品/店铺、操作人和摘要。批次/财务摘要只列变化字段，盘点摘要为日期/版本/差异，导入摘要为当前保存条数和状态。详情按以下类型展示：

- 字段修改日志：允许展示的业务字段逐项对比，另可展开完整前后业务字段；批次作废保留原因和原角色，原记录未保存原因时明确说明。
- 盘点保存版本：账面、实盘、差异、版本和备注，不伪造成库存调整或一次修改的前后值。
- 导入/撤销历史：文件、工作表、来源/结算/销售条数、重复和待确认数及当前状态；导入和撤销分两条事件，使用各自记录的操作人和时间。后续待确认处理可能更新计数，不是不可变审计快照。

## 权限及边界

| 来源 | 管理员 | 运营 | 查看者 |
| --- | --- | --- | --- |
| 批次更正/作废（含旧批次日志接口） | 全部共享 | 不可 | 不可 |
| 盘点版本 | 全部日期 | 不可 | 不可 |
| 销售导入/补录/撤销 | 全部 | 不可 | 不可 |
| 财务审计 | 财务增强启用且关联店铺存在时可见 | 不可 | 不可 |
| 商品、店铺/映射管理 | 全部共享 | 不可 | 不可 |
| 账号管理 | 全部 | 不可 | 不可 |
| 新批次入库 | 全部共享 | 不可 | 不可 |
| 销售处理、损益表保存 | 全部 | 不可 | 不可 |

统一日志的选项、列表、详情及旧GET /batches/{batch_id}/logs均由RequireAdmin保护，运营/查看者无论是否绑定店铺都返回403；服务层同样在查库前拒绝非管理员。管理员可按店铺或同次操作编号筛选，绑定店铺不缩小管理员范围。新增来源仅在审计表可用时提供；财务关闭时不查询财务可选表。此限制只针对操作日志查询，不改变入库、商品、销售处理、盘点或各模块业务历史的原权限，也不停止记录非管理员的业务操作。前后值按业务字段白名单投影，递归移除凭据和幂等键等字段，不输出原始结算JSON或报表payload。

导航默认隐藏，恢复管理员身份后才显示；非管理员直接调用页面切换或日志模块也不发起查询。退出或身份降权清空表格/弹窗，延迟响应校验当前管理员身份与会话代次，不能重新展示旧日志。旧批次弹窗脚本仅保留管理员兼容能力，批次列表不再挂载入口。

四个日志读取接口统一设置`Cache-Control: private, no-store`，包括正常响应及已处理的权限、校验和来源错误，避免浏览器/共享缓存保留日志。策略在[log_http.py](../../../services/log_http.py)的响应发送阶段应用，保留原序列化和异常处理；其他业务接口的缓存策略不变。两份页面的api助手透传请求级cache选项，统一日志及旧批次日志调用均显式使用`cache: no-store`，继续校验管理员和会话代次。

新策略不追溯删除旧版本已写入浏览器的缓存。升级后需清理一次既有浏览器缓存并刷新，前端no-store会绕过旧缓存；此步骤不涉及库存数据或历史日志删除。

财务摘要和详情共用按实体维护的finance_values投影：费用来源保留真实mode（manual/ledger），结算分类保留breakdown中已支持科目的金额，月度版本保留version及calculation_version。未知实体/字段不开放；request_key、source_digest和报表payload继续排除。界面翻译对应字段、操作及分类标签，不改写原审计JSON或历史版本。

## 时间与完整性

已有来源的时间语义并不统一：批次日志和盘点明确为UTC；销售导入的数据库默认时间、撤销的旧主机时间及财务审计默认时间没有完整时区元数据。本轮保留原时间，UTC来源明确标注，其他显示“原记录时间”；按原记录时间倒序，筛选原记录自然日，不能把跨来源排序视为已经核准的绝对时间顺序。没有改写旧时间或猜测主机/数据库时区。

新业务审计时间为UTC。旧来源时间语义继续如上，不为统一页面改写旧日期。缺来源表或临时查询错误返回503及稳定错误码，不显示虚假的空记录；可改为单独可用分类重试。启用扩展审计而缺表时相关写入503并回滚，页面显示结构未就绪；关闭时提示尚未启用/已暂停，保留读取已存在的审计表。未找到或越界详情404，不可见来源403。页面请求校验账号、会话代次和请求顺序；退出/同账号重登清除表格和详情，旧401/旧详情不能影响新页面。
